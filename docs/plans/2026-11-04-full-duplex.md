# 全双工：人的消息先处理，长任务放后台

- 日期：2026-11-04
- 相关：Bot 运行配置里「不派 DSH 子代理」仍然有效
- 代码：`ds-bot/src/host/steer.js`、`ds-bot/src/host/background.js`

## 为什么

一个 Bot 忙着跑工具或长任务时，人发来的下一句只能排队，或者插到下一步，当前这一步不结束就读不到。`/side` 能马上答，但不能用工具。人会觉得 Bot 是半双工的。

其他来源不能插队：别的 Bot、群、定时任务、后台结果，打断了会把正在做的事弄乱。

长任务如果占着 Bot 自己的会话，人的下一句就还是要等。所以长任务要换到另一个会话里做，做完再把结果送回来。DSH 的子代理用户看不见、停不掉，换段时还会被一起取消，所以这里不用它，由插件自己开一个普通会话。

## 已定的行为

### 人的消息先处理

- 只在 Bot 自己的私聊里。群会话的回合不因此被打断。
- 默认开。Bot 设置里的「先回答你」关掉之后，人的消息恢复成原来的样子：插话等到下一步，排队等到这一轮结束。
- 开着的时候，人的消息不论是插进下一步还是排到下一轮，都会停掉正在跑的这一轮：取消原因是 `ds-bot/steer`，收件箱留着，这条消息放到下一轮的最前面，新的一轮马上接着读它。已经写出来的回复不交给等回复的人；这一轮的派活关系交给新的一轮。
- 正在跑的 shell 会像原来的插话一样脱离到后台任务，这一步可以结束，命令继续跑。
- 别的 Bot、群、定时任务、后台结果不取消这一轮。它们仍按原来的规则排队或在下一步被读到。

### 后台任务

- Bot 在自己的私聊里调用 `start_background`（标题和任务说明）。群里不能调用。
- 任务先写入 `bot/background.json`，然后才开会话、才把任务发给那个会话。
- 每个 Bot 同时最多两个后台会话。再多的任务停在文件里，等有空位再开始。Bot 自己的会话不算在这两个里面，人的消息始终走它，不跟后台任务抢名额。
- 后台会话用这个 Bot 的工作文件夹、权限和模型，不挂团队工具。做完以后，结果以一条不打断的消息送回 Bot 自己的聊天，标题会出现在对话里。Bot 再拿这段结果回答人。
- 侧栏在 Bot 自己没在说话时显示正在跑的后台任务；打开的对话里也有一行。
- `stop_background` 停下一个。还没开始的直接取消；已经在跑的停掉之后，把已经写出来的内容送回来。
- 删掉 Bot 时，它的后台任务一起停掉。

### 重启

- 文件里还是「在跑」、会话已经做完的：把结果送回聊天，不再做一遍。
- 会话还没收到任务，或者任务被重启切断：补一次说明，让它接着做，不把已经做完的再做一遍。再被切断一次，就告诉 Bot 这次停了，不再自动重试。
- 还在排队、没有会话的：有空位就开始。

## 不做什么

- 不重新打开 DSH 的 `subagent` 等委派工具。
- 不让别的 Bot、群、定时任务或后台结果打断正在跑的回合。
- 不在群会话里跑后台任务。
- 不把后台会话登记成一个 Bot。

## 已知限制

- DSH 在工具已经开始执行之后才会等这个工具自己结束。取消会通知它停，但不抢在它返回之前把回合拆掉。不看取消信号的工具，人仍要等到这一步返回。
- 后台会话是普通 dsh 会话，用户不能在侧栏里把它当一条聊天打开。能看到的是 Bot 聊天里的状态和结果。
- 每个 Bot 两个后台名额，多出来的排队，没有全局池。
- 结果送出之后、从文件里删掉之前如果进程停了，重启可能把同一条结果再送一次。
